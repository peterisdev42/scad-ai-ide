# Agent shared capabilities and permissions

GUI, commands and Agent tools use the same domain services. The generated [tool catalog](agent-capability-catalog.md) lists each registered operation and its owner.

| Module     | Observed business operations                                                                                                                                                                       | Shared owner                                                    | Safety boundaries                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Runtime    | state, catalog, discovery/installed refresh, install exact build/archive, add executable, select, managed removal, installation cancellation                                                       | RuntimeService                                                  | trust, host paths/probing, one mutation gate, managed root, independent deletion confirmation                 |
| Customizer | target/schema/current/default values, set/reset one/all, list/select/new/save/delete/import/export presets                                                                                         | CustomizerDomainService + CustomizerService + CustomizerPresets | target/revision, atomic validation, per-target overrides, file merge/watch, independent deletion confirmation |
| Libraries  | registry state/search/refresh, project/dependency list, explicit project selection, install/remove/restore/repair, global inventory/verify one/all/repair, cleanup single/unused/all, cancellation | LibraryService + existing manager/store                         | workspace trust/root, exact versions, transactions/store locks, references, two-phase user-confirmed cleanup  |
| More       | GitHub status/silent refresh/interactive connect, Dev availability, cache metadata/inspect/clear one/scope/all                                                                                     | GitHub service + DeveloperCacheController                       | no tokens, hard Development guard, bounded redaction, disposable cache boundaries, per-entry errors           |

UI-only exemptions: Runtime tabs, Library tabs/query widget/project picker selection (business mutations instead take explicit project), Customizer groups/collapse/expand/focus/scroll, cache editor/reveal global folder, panel navigation. Registry search is a business read, not an exemption. Customizer reset-all is a business operation even when invoked by a toolbar.

## Service contracts

CapabilityContext carries caller identity, AbortSignal and operation progress. CapabilityHandler owns live availability and execution; CapabilityError provides explicit failure codes. GUI and Agent reuse module services; agents never dispatch Webview messages. Existing platform installers, locks, file formats, stores and Preview events remain authoritative.

Compatibility: retain VS Code ^1.140.0 and stable installed @types/vscode. Stable LM Tool API is present in the local type declarations. Official contribution reference documents path-based chatInstructions and chatSkills (SKILL.md parent/name equality). No proposed APIs.

Sources: [VS Code tools](https://code.visualstudio.com/api/extension-guides/ai/tools), [contribution points](https://code.visualstudio.com/api/references/contribution-points).

## Capability and authority decisions

- Every business operation above has an Agent path. Preset listing is part of `customizer.state`; selecting a project is explicit request identity on every Agent project action. GUI project-picker selection is presentation state, not a separate Agent operation. Project repair is existing lock-authoritative restore. Registry/library/version detail is available through search with an exact ID and bounded versions.
- GUI, commands and Agent share the same service instances, state, busy gates, platform transactions and events. Tools do not dispatch GUI messages or invoke input pickers. Tool invocation awaits completion and returns its terminal operation; other calls can inspect recent/running operations and request cooperative cancellation. Source changes/parameter events/preset changes increment Customizer revision; Runtime and Library service events increment exposed snapshot revisions.
- Runtime archive/executable paths are absolute paths on the workspace extension host. Agent preset file operations validate `file:` URIs, JSON suffix, canonical workspace membership and symlink escapes, including parent identity for new files. Agent dependency writes require exact known project plus canonical workspace membership. Existing GUI workflows with already-open external projects remain available; that does not authorize Agent writes outside the workspace.
- Runtime removal and preset deletion use independent modal service-side authorization. Dev clearing independently confirms the exact selected IDs and rejects changes during confirmation. No model-provided boolean grants approval. Confirmation functions are injected only by trusted construction in tests; they are never tool inputs.
- Library cleanup uses opaque, single-use, two-minute server plans with exact internal candidate/state digest. Planning reads cache/reference state without deleting resources or writing project files. Execution synchronizes known references, rejects stale/expired plans, obtains actual human authorization, then revalidates state/trust and uses existing locked GC protection. Unknown external projects remain outside the known reference index; the impact warning is preserved. Mode all deliberately supports the existing GUI authority to remove referenced global sources without modifying project manifests/locks.
- Cache access hard-rejects outside ExtensionMode.Development in both availability and the service. Agent reads expose metadata or one bounded/redacted preview; they never return raw bulk Mementos or cache contents. Cache values can still contain unrecognized personal data: preview is explicitly labeled. Managed runtimes/exporter/library source/reference indices remain excluded from disposable disk caches. Clear-all finishes requested entries and reports partial failures.
- GitHub authorization uses the actual interactive VS Code provider; tools return allow-listed status fields only. No access tokens enter tool context. GUI operates without any AI subscription. No proposed VS Code APIs or bespoke MCP/LLM backend were added.

## UI-only exemptions (four management panels)

Panel opening/navigation, Runtime Installed/Available tabs, Library Registry/Global/Project tabs, query-widget text, project-picker selection, Customizer group folding/collapse/expand/input focus/scroll/native scrollbar configuration, opening cache values in an editor, revealing the global folder, theme/highlight rendering and tooltips are presentation. Their underlying inspect/search/explicit project operations/reset-all/cache operations are covered above. Cancellation is a business capability and is exposed through operation cancellation.

## Discovery and verification

AI Panel lists all 42 tools in seven category tables with live availability and permission information, followed by two Instructions and six Skills. Refresh reads metadata only. The catalog and generated resource paths are checked by `npm run check:agents`.

Registration and GUI parity do not prove that a model can complete a workflow. See the [verification guide](agent-verification.md) for repeatable commands, observed model failures and environments that still require acceptance.


## Customizer source authoring

The three `customizer.sourceAnalyze/sourceApply/sourceValidate` capabilities belong to `CustomizerSourceDomainService`, separate from Override revisions and presets. They use the existing Parser's shared scanner and the pure source Analyzer/Editor/Validator. Problems and Quick Fixes use those same Core functions; the existing GUI still uses `parseCustomizer`.

Source identity is the complete URI, TextDocument version and UTF-8 SHA-256. Plan is read-only but requires trust; commit retains LM confirmation, consumes an opaque two-minute plan once, rechecks canonical workspace membership/trust/CAS, and submits bounded WorkspaceEdits without saving. Commit returns actual buffer analysis, applied and semanticPass separately. No model flag grants authority. Code Actions require normal trusted editor context and reuse the planner.

The service supports extension-host `file:` URIs only. Virtual/untitled/custom providers are rejected explicitly; SSH/WSL/container behavior needs real host acceptance. No recursive include/use, expression evaluation, geometry migration, preset writes or implicit Runtime/Preview execution is added. Ambiguous ordinary trailing comments and moves that would alter other parameters are refused. See [source authoring](customizer-source-authoring.md) for the supported contract and acceptance status.


Runtime state exposes `state.activeRuntime` as a complete selected CLI record (version, executable, argsPrefix, source/release metadata) regardless of installed-list pagination. `state.runtimes` uses the same discovered inventory as Runtime Panel and returns total/items/hasMore/nextOffset. `state.discovery` distinguishes restricted, discovering, notStarted, error and ready, including configured-path errors and bounded diagnostics. The list represents recognized installations on the extension host rather than an exhaustive client-machine scan; `runtime.builds` remains the downloadable release catalog. No extra tool is necessary.


## Required business parity

The agreed delivery scope is **Runtime, Customizer, Libraries and More**. Preview rendering, measurement, scene editing, exports and slicer workflows remain a separate follow-up. Within these four panels, every GUI business operation must have a shared-service Agent path. [GUI → Agent contracts](gui-agent-parity.md) is generated from actual GUI action classification plus schema-validated call examples; `check:agents` rejects missing examples, unknown capabilities, invalid arguments and stale output. Navigation, folding, scrolling and revealing an existing editor/folder are presentation, not substitutes for missing data or mutations.

Runtime equivalents: selected and installed CLI inventory (`runtime.state`), online catalog and forced online refresh (`runtime.builds`, refresh=true), exact build download (`runtime.installBuild`), offline archive (`runtime.installArchive`), executable registration (`runtime.addExecutable`), switching (`runtime.select`), managed deletion (`runtime.remove`), installed rescan (`runtime.refresh`, mode=installed), and cancellation (`operation.cancel`, domain=runtime). Installed flags and pagination are returned. Install/remove handlers verify inventory postconditions. Downloading alone does not promise selection.

`operation.cancel` now accepts exactly an Agent operation ID or a Runtime/Library domain. Domain cancellation uses the same abort controller as GUI-started jobs, including requests issued while mutation gates are busy; a cancellation request is not a terminal result. Library snapshots expose shared busy/cancellable/message/error activity so either origin can be observed. Registry search shares GUI installability, labels and cached flags. More returns redacted GitHub diagnostics and Development-only cache storage metadata; real authorization, removal confirmation and cache redaction remain enforced.

## CAD diagnostic increment

`cad.modelAnalyze` and `cad.issueDetails` extend the original 40 management tools without changing their schemas. Both commands and tools share the CAD domain/CLI path and the existing source Problems collection. CLI execution independently requires Workspace Trust even though analysis is read-only. The scope is CSG diagnostics; mesh/assembly/visual/printability checks remain unexamined. See [CAD architecture](cad-verification-architecture.md) and [acceptance](cad-agent-acceptance.md).
